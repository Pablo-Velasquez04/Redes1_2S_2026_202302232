### Instrucciones paso a paso (Cómo hacerlo en Packet Tracer)

1. Haz clic izquierdo sobre un switch (empecemos por el principal, el que conecta a todos los edificios).
2. En la ventana que se abre, ve a la pestaña que dice **CLI** (Command Line Interface).
3. Si ves un mensaje que dice `Press RETURN to get started!`, presiona la tecla **Enter** en tu teclado. Verás el prompt del switch, que normalmente dice `Switch>`.
4. Escribe los siguientes comandos (presiona Enter después de cada línea):

```ios
enable
configure terminal

```

*(Ahora notarás que el prompt cambia a `Switch(config)#`, lo que significa que estás en el modo de configuración global).*

### 1. Asignar el Nombre y el Mensaje MOTD

A continuación, cambiaremos el nombre del equipo y configuraremos el banner exactamente como lo pide el proyecto. Ingresa estos comandos (copia el texto tal cual):

```ios
hostname Core_DataCenter
banner motd #Acceso Restringido - TechPark_202302232#
exit
write memory

```

*Nota: El símbolo `#` se usa como delimitador para indicarle al switch dónde empieza y dónde termina el mensaje del banner. El comando `write memory` (o simplemente `write`) sirve para guardar la configuración para que no se borre si apagas el simulador.*

### Paso 1: Configurar el VTP y crear la VLAN Nativa (En el Switch Core)

Entra a la pestaña **CLI** de tu switch principal (`Core_DataCenter`) y aplica esta configuración para convertirlo en el servidor maestro y crear la VLAN 92 que usaremos como nativa:

```ios
enable

name NATIVA
```

*Nota: El switch Core distribuirá esta VLAN y este dominio al resto de la red.*

Ahora debes ir a la **CLI** de **todos los demás switches** de la topología (Servidores, I+D, Edificio Corporativo y Producción) e ingresar exactamente esto para que obedezcan al servidor:

```ios

configure terminal

vtp domain Smart_3
vtp password proyecto12S2026

```

### Paso 3: Configurar los Enlaces Troncales y aplicar la VLAN Nativa

Los puertos troncales son los que conectan un switch con otro switch. **Debes hacer esto en ambos extremos de cada cable que conecte switches**.

Para no hacerlo uno por uno, Packet Tracer permite usar el comando `interface range` para seleccionar varios puertos al mismo tiempo. Por ejemplo, si tu Switch Core conecta a los otros edificios usando los puertos `Gig0/1`, `Gig0/2` y `Fa0/24`, la configuración sería:

**En el Switch Core:**

```ios
interface range Gig0/1-2, Fa0/24 
switchport mode trunk
switchport trunk native vlan 92
exit
write memory

```

**En los Switches Clientes:**
Ve a los switches que están al otro lado de esos cables, identifica el puerto que sube hacia el Core o hacia otro switch (por ejemplo, `Fa0/1`), y configúralo igual:

```ios
interface Fa0/1
switchport mode trunk
switchport trunk native vlan 92
exit
write memory

```

### ¿Cómo saber si funcionó?

En el switch Core, escribe el comando `show vtp status`. Deberías ver que dice "VTP Operating Mode: Server" y "VTP Domain Name: Smart_3". Además, las luces naranjas de los cables volverán a ponerse verdes tras unos segundos.

Basado en tu carné par (202302232), aplicaremos el protocolo PVST. La decisión arquitectónica es forzar al Core_DataCenter para que sea el Root Bridge de todas las VLANs; esto centraliza el flujo de datos, minimiza los saltos de red y asegura que los puertos bloqueados por STP queden en los anillos periféricos (como I+D y Edificio Corporativo) y no en el núcleo.1.Configurar el modo PVST:En TODOS los switches.Ingresa a la CLI de cada switch de tu topología (Core, I+D, Edificio Corporativo, Servidores, Producción) y asegúrate de que operen explícitamente en este modo.iosenable
configure terminal
spanning-tree mode pvst
exit
write memory
2.Modificar la prioridad para forzar el Root Bridge:Solo en Core_DataCenter.Ve a la CLI de tu Core_DataCenter. Modificaremos la prioridad a 4096 (el valor por defecto de los demás será 32768) para garantizar que este switch gane siempre la elección del puente raíz para todas tus VLANs.iosenable
configure terminal
spanning-tree vlan 1,12,22,32,42,52,92 priority 4096
exit
write memory
